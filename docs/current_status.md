# Current Status (v0.11)

## v0.11：词汇表可以在本机合并成一张（不调 AI）

- **新功能：合并已有词汇表**（决策 37）。基础模式「词汇表」那一行多了一个
  `合并已有词汇表…`：把之前几次运行生成的「重难点词汇表」拖进来（或整个文件夹加进来），
  合成一份、去掉重复。**纯本地，一次 API 都不调，没配密钥也能用。**
  - **实测**（老师手上 9 份表，其中 2 份是「阅读词汇」和「语法变形」分开的）：
    阅读词汇 **1166 → 1032**，语法变形 **837 → 713**，两秒出结果。
  - 去重规则见决策 37。一句话：**阅读词汇按单词去重**（同一个词的多个词性并成 `n./v.`，
    释义按义项取并集，带「熟词生义」注释的写法优先）；**语法变形按「基础词 + 变形词」去重**，
    考点说明只留信息量最大的一条；两表都按字母排序（汇总表是查的，不是读的）。
  - 认不出表头的表格**跳过并写明原因**，一份都认不出就报错，不写空表。
  - 产出仍然走 `export_vocab_docx.build`，版式/边框/分页/两道闸门全部继承。
  - 命令行：`python3 scripts/merge_vocab_docx.py <文件或文件夹>… [--out 合并.docx]`
- **修 bug：词汇表填表是 O(行数²)**。`table.cell(r, col)` 每次调用都重建整张表的单元格矩阵；
  单卷 250 行看不出来，合并后的 1032 行那张表要 63 秒（两张表合计 147 秒）。
  改成按行遍历新增行的 `tc`，输出一模一样，瞬间完成。
- **修 bug：后台任务的结果回调跑在工作线程上**。`_Check.finished` 连的是闭包，
  闭包没有 receiver object，Qt 就在**发信号的那个线程**里执行它——于是
  「API 测试」和「合并词汇表」的界面更新都在工作线程里动控件（Qt 会打印
  `Cannot create children for a parent that is in a different thread`）。
  改连 QObject 的**绑定方法**，投递变成排队到界面线程。

# Current Status (v0.8)

## v0.8：不再只能连 DeepSeek；词汇表两条路，老师自己选

- **词汇表二选一**（决策 33）。基础模式加了一行「词汇表」，两个单选：
  - **完整（分块）**——逐题提词（18 次调用），词表**逐题对应**学生手上的卷子，一个字都不多。
  - **困难（整卷）**——通读整卷（自动去掉答案区，3 次调用），模型能判断「这个词在**这份卷子**里
    算不算难」，代价是词表里会有学生没做到的题的词。**默认。**

  哪个更好取决于老师怎么用这张纸，**不该由代码替她决定**——上一版单方面改成整卷是越权了。

  **实测（三份样卷，flash + 最深档，两边都没截断）**：

  | | 完整（分块） | 困难（整卷） |
  |---|---|---|
  | 调用数 | 18 | 3 |
  | 花费 | **¥0.44** | **¥0.15** |
  | 耗时 | ~13 分钟 | ~6 分钟 |
  | **词数** | **234 词 / 202 词形** | **104 词 / 73 词形** |
  | 缓存命中 | 68% | 99% |

  **「完整」名副其实**：词是整卷的 2.25 倍，代价是贵 2.9 倍、慢一倍。这就是取舍本身。

  - **导出闸门认词表自带的模式，不认命令行**：老师可能拨了开关但没重跑 vocab。
    分块词表换了题就过期（必须重跑）；整卷词表换题不过期。
  - 盘上的老词表没有这个字段，按**形状**认：有 `item_id` 的是分块。

- **多 provider**（决策 30）。`scripts/providers.py` 一张表描述每家 API：
  DeepSeek / OpenAI / Claude / GLM / Qwen / 自定义，外加一批**预留占位**
  （Kimi、豆包、MiniMax、硅基流动、OpenRouter、本地 Ollama——都只是表里一行）。
  只填 `--provider` 就够：接口地址、密钥变量、模型名全从表里取。
  - **各家唯一真正不兼容的是「思考怎么写」**：DeepSeek 是 `reasoning_effort`+`thinking`，
    OpenAI 只有 `reasoning_effort`（且用 `max_completion_tokens`、**不收 `temperature`**），
    GLM/Qwen 是 `enable_thinking`（**必须走 `extra_body`**，当普通关键字传给 OpenAI SDK 会被静默丢掉），
    Claude 走原生 `/v1/messages`（`x-api-key` + `output_config.effort`，**传 `temperature` 直接 400**）。
  - **档位自适应**：老师看到的还是「标准 / 深度」两档，由 provider 解析成它**真实存在**的档位。
    **GLM 根本没有强度维度**——界面就如实显示「不可调」，而不是画一个不起作用的开关。
  - **模型 ID 会下架换代**（GLM 4.6/4.7 已于 2026-07-09 下架），所以「刷新模型列表」
    （`GET /v1/models`）是必需品。价格未知的模型显示「未配价格，未计入」，**绝不按别家的价瞎算**。

- **整卷这条路的做法**（决策 29；现在是默认，但不是唯一）。读 `extracted_text/<卷>.txt`，
  一份卷子一次调用。
  - **必须先砍掉答案区**：那里面有答案键和**参考范文**——范文是学生手上那份卷子里**没有**的文本。
    实测三份卷砍掉 43%–59%。分块那条路不用管这个：`segment_body` 本来就只有题干。
  - **换一批题不让整卷词表过期**（词本来就是整卷的）。分块词表会过期。

- **两个 preset 都跑最深档**，vocab 也不例外（决策 31）。这是**明知故犯**地重踩决策 9 的坑，
  而且实测证明那个坑是真的：**94% 的输出 token 花在了思考上**，单次最差 38,934 输出里
  37,022 是思考，只用约 1,900 token 写 JSON。**16,000 的老上限下三次调用会全部截断。**
  - 护栏从「限制 effort」换成「放大 output」：`--vocab-max-tokens` 22000 ×3 = 64,000，
    对实测峰值留 39% 余量；截断即硬失败，并按**这个模型真实有的旋钮**告诉你怎么修。
  - **对照组**：flash + high 输出只有 17,188、耗时 192s（vs 833s）、花费 ¥0.05（vs ¥0.19），
    而**词数几乎一样**（114 vs 116）。深度档在这个抽取任务上买不到判断力，只买到了思考链。
    真要省，把 vocab 钉回标准档就行——一行 PRESETS 的事。
  - **⚠️ GLM / Qwen 的输出上限（32k / 32,768）低于实测峰值**，深度档下可能截断。
    `run_vocab` 开跑前会警告。

- **PDF 多一个后端：MinerU 官方云 API**（决策 32）。和 PaddleOCR 产出同样的 `OcrBlock`，
  排版完全一致。MinerU 是**异步**的（提交→轮询→下载 zip），轮询循环走 `_sleep_or_cancel()`，
  否则按取消会卡在里面。

- **修掉一个真 bug**：`Conversation` 的 token 计数在某轮没返回 usage 时会**静默冻住**，
  天花板从此永不触发、会话无限增长。现在取「API 报的值 和 本地估算」的大者。

# v0.7

工具改名为**英语试卷整理工具**（不再只是「高三」），有了自己的图标。

- **本版最重要的一条**：**新电脑上装了用不了的 SSL 故障**（决策 24）。
  学校/公司代理或杀毒软件会在中间拆 TLS 并用自己的根证书重签——macOS 信任它，
  但 Python 抱着自带的 CA 列表看不见，于是 API 测试直接报
  `self-signed certificate in certificate chain`，**整个 App 等于废了**。
  现在用 `truststore` 走 macOS 钥匙串；`--selftest` 会断言冻结包确实走的是钥匙串，
  否则不出 DMG。**本机复现不了中间人环境，真正的验收是在那台电脑上再点一次「测试」。**

- **取消真的能取消了**（决策 25）：以前只在阶段之间查一次标志，解析跑到一半按取消要等几分钟。
  现在检查点铺到每道题、每一轮、每次发请求之前，退避也能被叫醒；
  **正在飞的请求会被 `shutdown()` 拆掉**（只 `close()` 唤不醒阻塞在 socket 上的 worker——测试抓出来的）。
  调 AI 时按取消会先弹确认框，如实写明：已生成的保留、正在生成的作废、
  **已发出的请求可能仍计入用量**（DeepSeek 没有「停止生成」接口）。

- **思考强度只剩 high / max**（决策 26）：DeepSeek 把 `low`/`medium` 都映射成 `high`，
  所以原来的四档滑块**从来没起过作用**。
  （v0.8 起：档位由 provider 声明，DeepSeek 仍是这两档；两个 preset 都跑最深档，见决策 31。）

- **界面**（决策 28）：
  - 文案里不再谈钱（有测试守着）；跑完的花费读数照常显示。
  - API 密钥改成**弹窗**——它展开时会把标签页顶掉，而且密钥本来就是设一次的东西。
  - **进阶模式两栏**，默认窗口下一屏看全，不用滚动。
  - 详细日志**默认开启**（盯着空日志三分钟，谁都以为它卡死了）。

- **教师版标题**：`AI 详细解析` → **`详细解析和解答步骤`**（老师拿这份去讲课，标题上写着 AI 不合适）。

- **`--init` 的护栏**不再依赖 `Path.cwd()`（打包后 cwd 是 Finder 给的随机目录，那个护栏形同虚设）。
  行为不变：整轮「开始整理」仍会先清空输出目录，分步重跑仍然不会。

- **又一个引号坑**（决策 27）：只说「不要用英文双引号」，flash 会把 JSON 的**键名**也写成
  `{“word”: “x”}`——vocab 阶段真的挂在第 9 项。现在 prompt 把「语法符号」和「字符串内部」
  分开讲并给正反例，纠正回合也按实际犯的错来说话。

## 闸门（任何一条不过就直接失败）

- `docx_splice.validate()`: XML 可解析 / A4 纵向 / 无未定义样式 / 无悬空 rId / 成对标记配平。
- `assert_student_edition_is_clean()`: 学生版不得含来源/解析/范文/答案键/`**`。
- `assert_selection_is_complete()`: 选中的题必须都有解析；词汇表必须覆盖当前选题。
- `OfficialExplanations.blocks_for()`: 区间内混进别的题号一律返回空——宁可不印，也不能印错题的解析。
- `require_parsed()`: 模型 JSON 解析失败不许静默降级（先给一次**对症的**纠正回合，再错才硬失败）。
- `scripts/check_export_quality.py`: 跑完一轮后的整体体检（23 项）。
- `app/main.py --selftest`: 冻结包里必须能加载 prompt 模板、tokenizer，**且 TLS 走的是系统钥匙串**。

## 已知限制

- **SSL 的最终验收只能在那台出问题的电脑上做**——本机没有中间人环境可复现。
  若 truststore 仍不通，说明拦截根证书压根没进钥匙串，只能去调试模式勾「跳过 HTTPS 证书校验」。
- 候选池小的时候「换一批题」换不彻底：3 份卷＝每个题型只有 3 个候选、要选 2 个，最多换掉一道。
- 写作题原卷只给范文、不给逐题解析，所以「官方答案与解析」一段印的是原卷范文。
- 输出的 Word 文件名仍是「高三英语精选试题_…」——那是产物的名字，不是工具的名字，本次没动。
- 取消在**本地阶段**是立刻停；API 阶段是断连后停（几秒内）。
